# Claude Code 2.1.133（中文版）

- 新增 `worktree.baseRef` 设置（`fresh` | `head`），用于选择 `--worktree`、`EnterWorktree` 和 agent-isolation worktrees 是从 `origin/<default>` 还是本地 `HEAD` 创建分支。**注意：**默认值 `fresh` 会把 `EnterWorktree` 的基准改回 `origin/<default>`（自 2.1.128 起一直是本地 `HEAD`）——如需在新 worktrees 中保留未推送提交，请设置 `worktree.baseRef: "head"`
- 新增 `sandbox.bwrapPath` 和 `sandbox.socatPath` managed settings（Linux/WSL），用于指定自定义 bubblewrap 和 socat 二进制文件位置
- 新增 admin-tier key `parentSettingsBehavior`（`'first-wins'` | `'merge'`），让管理员可以选择将 SDK `managedSettings`（parent tier）纳入策略合并
- Hooks 现在会通过 `effort.level` JSON input field 和 `$CLAUDE_EFFORT` 环境变量接收当前 active effort level，Bash tool commands 也可以读取 `$CLAUDE_EFFORT`
- 优化 focus mode 行为
- 优化内存使用：在内存压力下释放 warm-spare background workers
- 修复 refresh-token 竞争清空共享凭据后，并行会话全部以 401 失败的问题
- 修复作用域为 drive root（`C:\`）或 POSIX `/` 的 `Edit`/`Write` allow rules 匹配错误并总是弹出提示的问题
- 修复当历史文件或 session-log 文件锁因时钟偏移或磁盘较慢而受损时出现未处理 rejection（`ECOMPROMISED`）的问题
- 修复对话压缩期间按 Esc 会显示虚假的 "Error compacting conversation" 通知的问题
- 修复完整 MCP OAuth 流程未遵循 `HTTP(S)_PROXY` / `NO_PROXY` / mTLS 的问题，包括 discovery、dynamic client registration、token exchange 和 token refresh
- 修复通过 `--add-dir` / SDK `additionalDirectories` 传入的 mapped network drives 上 Read/Write/Edit 被拒绝的问题
- 修复来自 claude.ai 的 Remote Control stop/interrupt 没有像本地 Esc 一样完全取消 CLI 会话的问题，该问题会导致中断卡住的 tool 或 prompt 后，队列中的消息无法继续推进
- 修复一个会话中的 `/effort` 意外改变其他并发会话 effort level 的问题，以及相关的 IDE effort 变更可能被静默丢弃的问题
- 修复 subagents 无法通过 Skill tool 发现 project、user 或 plugin skills 的问题
- `claude --help` 现在会在 `--remote-control-session-name-prefix` 旁列出 `--remote-control`
- [VSCode] 修复扩展构建未打包 Claude binary 时，`claudeCode.claudeProcessWrapper` 因 "Unsupported platform" 失败的问题
