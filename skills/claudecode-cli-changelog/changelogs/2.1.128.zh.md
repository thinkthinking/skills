# Claude Code 2.1.128（中文版）

- 不带参数的 `/color` 现在会随机挑选一个会话配色
- `/mcp` 现在会显示已连接服务器的工具数量，并标记那些连接成功但工具数为 0 的服务器
- `--plugin-dir` 除了目录之外，现在还支持 `.zip` 插件归档
- `--channels` 现在支持 console（API key）认证方式——使用托管设置的 console 组织必须将 `channelsEnabled: true` 显式开启
- 优化 `/model` 选择器：折叠了重复的 Opus 4.7 条目，当前 Opus 现在直接显示为 "Opus"，而不再是 "Opus 4.7"
- 子进程（Bash、hooks、MCP、LSP）不再继承 `OTEL_*` 环境变量，因此通过 Bash 工具运行的 OTEL 接入应用不会再误连到 CLI 自身的 OTLP 端点
- MCP：`workspace` 已成为保留的服务器名——已存在的同名服务器会被跳过并给出警告
- 重新连接的 MCP 服务器不再每次重连都把完整的工具名清单刷进会话——再次声明的工具会按服务器前缀汇总展示
- SDK 宿主现在会收到持久化的 `localSettings` 建议用于 Bash 权限确认，因此选择 "Always allow" 会写入 `.claude/settings.local.json`
- `EnterWorktree` 现在按文档说明从本地 HEAD 创建新分支，不再从 `origin/<default-branch>` 切出——未推送的提交不会再丢失
- Auto 模式：当分类器无法评估某个动作时，错误信息会附带提示（重试、`/compact`，或加 `--debug` 运行）
- 修复在提交新 prompt 时焦点模式会短暂将上一条响应变暗的问题
- 修复在 Kitty 等会把 OSC 9 解释成通知的终端里，每次 `/exit` 都会跳出一个 "4;0;" 桌面通知的问题
- 修复 Remote Control 触发限流时只显示一句空的 "Opening your options…"、而没有可执行升级选项的问题
- 修复拖拽上传图片在读取失败时卡在 "Pasting text…" 不退出的问题
- 修复通过 stdin 向 `claude -p` 输入超过 10 MB 的内容时崩溃循环的问题
- 修复全屏模式下，长 URL 在换行后只有第一行可点击的问题
- 修复 `/plugin` 组件面板对通过 `--plugin-dir` 加载的插件显示 "Marketplace 'inline' not found" 的问题
- 修复当 MCP 服务器同时返回 structured content 和 content blocks 时，工具结果中的图片被丢弃的问题
- 修复列表项内的代码围栏复制时携带了多余前导空白的问题
- 修复 `/config` 中按 Tab 切换会让焦点丢失的问题——Tab 标题栏现在持续保持焦点，方向键和 Esc 都能继续工作
- 修复在不支持 OSC 8 超链接的终端里 markdown 链接文字会丢失的问题——现在以 `label (url)` 形式渲染，而不再只显示 URL
- 修复在使用更小自动压缩窗口的 1M 上下文模型上，会话被错误地以 "Prompt is too long" 拦截、还没到达真正的 API 上限的问题
- 修复并行 shell 工具调用中：一条只读命令（grep、git diff、ls）失败时会连带取消同批次其他命令的问题
- 修复对不支持 effort 的模型仍然在 banner 里显示 "with X effort" 的问题
- 修复在第三方 provider 上输入 `/fast` 会被模糊匹配到无关 skill、而不是提示 "not available" 的问题
- 修复 Bedrock 默认模型被解析成 `global.*` 而不是当前区域对应前缀的问题
- 修复 vim 模式：NORMAL 模式下的 `Space` 现在会把光标右移，与标准 vi/vim 行为一致
- 修复终端进度指示器（OSC 9;4）在两次工具调用之间会闪烁消失的问题——整轮交互期间持续显示
- 修复在最后一条记录是 compact 边界的恢复会话上、`/rename` 不带参数会失败的问题
- 修复 `--resume`/`--continue` 之后会出现来自之前会话的过时 "remote-control is active" 状态行的问题
- 修复 `installed_plugins.json` 中指向已删除缓存目录的过时条目污染 PATH 的问题
- 修复设置了 `CLAUDE_CODE_SHELL_PREFIX` 后，MCP stdio 服务器在参数包含空格或 shell 元字符时收到损坏参数的问题
- 修复 sub-agent 进度摘要没有命中 prompt cache 的问题（`cache_creation` 减少约 3×）
- 修复 `/plugin update` 一直检测不到 npm 来源插件新版本的问题
- 修复 sub-agent 在 transcript 没有变化时仍然反复触发摘要的问题，封顶了空闲 sub-agent 的最坏 token 成本
- Headless `--output-format stream-json`：`init.plugin_errors` 现在除了依赖降级失败之外，也会包含 `--plugin-dir` 加载失败
