# Claude Code 2.1.143（中文版）

- 新增插件依赖强制校验：当另一个已启用插件依赖目标插件时，`claude plugin disable` 现在会拒绝禁用（并给出可复制粘贴的禁用链提示），`claude plugin enable` 会强制启用传递依赖
- 在 `/plugin` marketplace 浏览面板中新增预计上下文成本（每轮和每次调用的 token 估算）
- 新增 `worktree.bgIsolation: "none"` 设置，允许后台会话不经过 `EnterWorktree`，直接编辑当前工作副本，适用于 worktree 不现实的仓库
- PowerShell tool 现在会传入 `-ExecutionPolicy Bypass`。可通过 `CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1` 退出该行为
- 后台会话从 idle 唤醒后，现在会保留你设置的 model 和 effort level
- 已附加的 agent 会话中，Shift+Tab 现在会把 auto mode 纳入循环
- 修复损坏的 `.credentials.json` 中 `scopes` 为非数组值时，会导致 CLI 启动挂起或 OAuth token refresh 静默中止的问题
- 修复 Windows Terminal 和 WSL 中 `claude agents` 的右键粘贴问题
- 修复 stop hooks 反复阻塞导致无限循环的问题：现在连续阻塞 8 次后，本轮会以警告结束（可通过 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 覆盖）
- 修复 Claude 在 `/loop` 迭代间 idle 时，Esc/Ctrl+C 无法取消待处理 wakeup 的问题
- 修复后台 shell 或委派的 subagents 仍在运行时，`/goal` evaluator 仍会触发的问题
- 修复 settings.json `env` 中的 `NO_COLOR`/`FORCE_COLOR` 会剥离 Claude Code 自身 UI 颜色的问题；现在它们仅应用于 subprocesses
- 修复 Windows 上 agent view 在列出会话时会反复生成 PowerShell 进程的问题
- 修复 `/bg` 不带 prompt 时会向 fork 出来的会话发送 "continue" 的问题；现在该 fork 会等待输入
- 修复不带 `plugin:` 前缀时，`--agent <name>` 找不到插件贡献的 agents 的问题
- 修复从 agent view 删除会话时不会移除其 transcript 文件的问题
- 修复 Windows Terminal 中滚动已附加后台会话时的 stale-fragment 渲染问题
- 修复主机睡眠或 macOS App Nap 之后，后台 agents 会误判 worker stall 并触发告警风暴的问题
- 修复 5xx 错误消息指向 status.claude.com，而不是显示已配置 gateway 或 cloud provider 名称的问题
- 在 Windows 上，Bedrock、Vertex 和 Foundry 用户现在默认启用 PowerShell tool。可通过 `CLAUDE_CODE_USE_POWERSHELL_TOOL=0` 退出。
- `claude agents` 现在接受 `--add-dir`、`--settings`、`--mcp-config` 和 `--plugin-dir`，并将它们应用到 dashboard 以及从中派发的后台会话
- `claude agents` 接受 `--permission-mode`、`--model`、`--effort` 和 `--dangerously-skip-permissions`，用于设置从该视图派发的会话默认值
- `claude --bg --dangerously-skip-permissions` 现在会在 retire→wake 后继续保留
- 修复后台会话会静默捕获 IDE file references 到 warm spare 输入中的问题，该问题会导致引用被追加到下一条从 `claude agents` 派发的 prompt 前面
- 当 `git worktree remove` 失败时，worktree 清理不再回退到 `rm -rf`，以避免丢失 gitignored 或进行中的文件
- 修复 macOS 上 background-job sessions 即使已授予 Full Disk Access，在读取 `~/Documents`、`~/Desktop` 或 `~/Downloads` 下文件时仍出现 "Operation not permitted" 的问题。
- `/bg` 现在会保留 `--mcp-config`、`--settings`、`--add-dir`、`--plugin-dir` 和 `--strict-mcp-config`，因此 backgrounded sessions 在 respawn 后仍会保留 MCP servers 和 settings。
- 从 `claude agents` 启动的后台会话现在会遵守 settings.json 中的 `permissions.defaultMode`（此前会被覆盖为 auto mode）
- 修复：Windows 上，当 response 正在 streaming 时在 `claude agents` 中按 ←，可能会让 agents 列表对所有输入无响应
- `/bg` 和 `←`-detach 现在会保留 `--fallback-model`，因此 backgrounded workers 在过载时会降级到 fallback model，而不是直接失败。
- `/bg` 和 `←`-detach 现在会保留 `--allow-dangerously-skip-permissions`，因此 fork 出来的 worker 会在 Shift+Tab 循环中保留 bypass-permissions 可用。
- 修复：当 `~/.local/bin/claude` launcher 缺失或不可执行时，background daemon spawn 现在会回退到正在运行的 binary
- 修复 `claude agents --allow-dangerously-skip-permissions` 会默认把派发的会话设为 bypass mode，而不是让它在 permission cycle 中可用的问题
